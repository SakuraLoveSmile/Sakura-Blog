## 唯一参照

- **问题参照**：`before-large-mismatch.webp`（用户 2026-11-10 02:10 截图，2x，视口约 1219 CSS px）。
  同一行两个「大」档：访问时段 `6 列 × 40 行`、Stellar 版本 `6 列 × 25 行`，宽度相同、高度相差约 63%。
- **视觉规范**：`resource/apple-design/` 的深色语义 token、Card / Button 模式；Console 永久深色，不验收浅色分支。
- **布局真值**：`modules/console/web/src/modules/dashboard/widgets/layout.ts` 的 `WIDGET_PRESET_SPECS`；
  网格 `cellHeight: 8`（`DashboardGrid.vue`）。改完后矩阵是唯一真值，组件不再自带尺寸。

## 已确认决定（方向 A）

1. 同一断点下的同一档位**只有一个足迹**：所有已注册组件共用同一个 w×h。
2. 档位是「盒子」，不是「内容档」：内容密度随档位变化，但盒子的尺寸由档位唯一决定。
3. 组件的 `minW`/`minH` 不得高于所属断点最小档位，避免钳制把统一足迹改回不一致。
4. 既有 4 个档位异常随统一足迹一并消失，不再单独修补。
5. **已确认（2026-11-10）**：lg「大」取整行 `12×40`；六张统计卡的「大」用 hero 居中排版，不设例外。

| 断点 | 小档渲染 | 中档渲染 | 大档渲染 |

| lg | 273×108 | 566×204 | 1152×300 |

- 已知边界：空态组件（访问趋势/时段/热门/最近评论）在夹具里没有数据，只验证了不裁切与空态居中。

## 代价与风险（实施前已知）

1. 「大」全部为整行宽度后，两个大卡片不能再并排；截图里并排场景会变成上下两行。
2. 小档从 3 列起步，趋势 / 时段 / 分类三个组件需要新增 mini 渲染，是本次主要工作量。
3. 统计卡在大档是「hero」排版，内容天然比图表少，填充度按 45% 验收而不是 60%。
4. 旧布局首次加载会重排一次（落到新档位），属于预期行为。
