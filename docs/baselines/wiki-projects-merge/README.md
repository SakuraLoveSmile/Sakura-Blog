# 项目管理合并基线（BLG-20261109-04）

Console「文库 + 项目管理」合并为单一「项目管理」入口的参照图、验收清单与实测证据。

## 1. 唯一参照图

- **来源**：用户 2026-11-09 提供的 Console 侧栏截图（原图 415×159，`image/webp`），显示「文库」（带下拉箭头）与子项「项目管理」两个叠加的菜单按钮。
- **本地归档副本**：`docs/baselines/wiki-projects-merge/reference-before.webp`（原图副本，未重编码）。
- 参照内容：侧栏「内容」组里「文库」是带 `children` 的父项，展开后出现子项「项目管理」——正是需要合并掉的两级结构。
- **本次不是重设计**：只把两个入口合成一个、把文档降为项目下的二级页面；沿用现有 `VPageHeader`、`VButton`、`VCard`、`VEmpty`、`apple-*` 表单控件与 Console 语义 token，不新增裸色值、第二套按钮样式或平行组件。

## 2. 视口规范

| 视口 | 宽度 | 要求 |
| --- | --- | --- |
| 桌面 | 1280×800 | 项目列表左右分栏；文档工作台左树右编辑器；页头四项操作一行放得下 |
| 手机 | 390×844 | 两页都无整页横向溢出；页头操作换行但不压标题 |

## 3. 验收项

### 3.1 侧栏与落地
- [x] 侧栏「内容」组只有一项「项目管理」（`ri:stack-line` 图标），不再有「文库」入口。
- [x] 「项目管理」没有子项：项目链接内只有 1 个 svg（无展开箭头），点击不再展开二级菜单。
- [x] 点侧栏或直接访问 `/console/wiki` 都落到 `/console/wiki/projects`。

### 3.2 项目列表（落地页）
- [x] 页头标题「项目管理」，副标题说明管理文库项目元数据。
- [x] 页头操作：「编排文档」（未选中项目时禁用）与「新建项目」。
- [x] 每个项目行有一个独立的「文档」按钮，点击进入该项目文档工作台；整行点击仍是「选中并编辑该项目」，两者互不影响。

### 3.3 文档工作台（项目二级内容）
- [x] 地址为 `/console/wiki/<project>/docs`，项目来自路由参数。
- [x] 页头标题「项目管理」，标题旁徽标显示当前项目名；副标题写明正在编排哪个项目的文档。
- [x] 页头不再有「选择文库项目」下拉；操作为「导入文章 / 返回项目 / 新建文档」。
- [x] 访问不存在或无权限的项目时显示「项目不存在或无权限查看」空态与「返回项目管理」按钮，不静默切到第一个项目。
- [x] 文档树、新建文档、编辑保存、删除、从文章导入的行为与合并前一致。

### 3.4 产物与证据
- [x] Playwright 用重建后的 Console 产物跑验收：入口 HTML 与磁盘 `dist/index.html` SHA256 一致，页面引用的入口资源与磁盘逐字一致。
- [x] 桌面 1280×800 与手机 390×844 两页都无整页横向溢出；四张截图见下。
- [x] `browser-evidence.json` 记录侧栏入口数、落地 URL、文档 URL、空态验证与视口。

### 3.5 390px 项目行（BLG-20261109-05 修复）
- [x] 长 slug 的项目行不再把「N 篇文档」挤成逐字竖排：slug 省略号截断、`title` 保留完整 id，文档数与分隔点 `shrink-0 whitespace-nowrap`。
- [x] 修复前实测：`0 篇文档` 被折成 4 行、高 64px（元信息列仅 16px 宽）；修复后 1 行、高 16px、宽 47px。
- [x] e2e 增加硬断言「文档数 span 高度 ≤ 20px」；去掉修复代码后该断言实测报错（高度 64px），确认用例能拦住回归。

### 3.6 390px 文档页空态的可见性（不是缺陷）
- [x] 空态卡片正常渲染并断言通过：`选择左侧文档开始编排` 存在，按钮「新建文档 / 导入文章」都在 DOM 内。
- [x] 首屏（844px 高）时它位于折叠线以下：页头 140px + 概览 179px + 文档树卡片之后，标题在 y≈793，底部导航顶边 y≈787。
- [x] `main.content` 可正常滚动（scrollHeight 1136），滚到底后标题移到 y≈501，空态完整可见；不构成内容丢失。
- 说明：该纵向密度（概览 + 文档树 + 空态）合并前就存在，本次不扩大范围改版式；如需「空态上移」另开任务。
