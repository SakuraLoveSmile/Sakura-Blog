## 与画板的有意差异

1. 橙色圆点 = 相对上次保存的未保存修改；“恢复默认”= 移除草稿里的显式覆盖，只在存在显式覆盖（或有未同步输入）时出现，与值是否等于默认无关（画板的全新安装故事里这两件事重合）。
2. 总开关关闭时依赖项整行变淡、仍可编辑（画板置灰），保持“可提前配置”；解释句在同一分区只在第一个依赖项上可见，其余只留给读屏。
3. 配色全部取自 Console 现有语义 token；Console 本身恒为深色（`<html class="dark">`），没有浅色/自动模式。“浅色/深色/自动”是前台主题的配色选项，不是 Console 的外观。
4. 前端预览面板沿用现有的底部停靠（打开时保存栏停在其上方），不改为侧栏。
5. 主题外观的颜色、字体、形状、背景沿用通用结构化编辑器，不逐项重画画板里的定制控件；行内名称把 `theme.appearance.preset` 显示为“预设”、`theme.appearance.typography` 显示为“正文排版”（分区标题已含原词），字段路径不变。
6. 结构化节点（导航、页面与侧栏、扩展等页）里的布尔开关用纯 CSS 放到右侧、名称与说明在左，与规范行一致；模板结构、子节点关系与保存路径不变。
7. 手机上分段选择占满整行（选项按文字宽度分配，命中区 ≥44px），名称与说明保持完整宽度，对应画板 `MobilePage` 里“段落首行缩进”的堆叠；只有开关和数字仍与名称同行。
8. 手机宽度下打开前端预览（底部停靠，占 65vh）时，sticky 页头 + 保存栏 + 预览面板合计占满视口，没有可用的聚焦区域；关闭预览即可。这是既有的预览停靠方式带来的限制，本任务没有改它。
9. 手机上沿用的小控件视觉不变，只扩大点击区（用户指示“只扩大点击区”）：开关（共享 `VSwitch`，51×31；画板手机稿里是 48×28）、“恢复默认”（48×18；画板手机稿里高 32px）、折叠摘要（21px 高）、不透明度滑块（28px 高）看上去仍是原来的大小，点击区在手机上补到 ≥44px。唯一已知的外观差异：不透明度滑块的键盘聚焦环在手机宽度下由 28px 高变为 44px 高。见 Q2b。
10. 页面标题下没有“效果说明条”（用户体验后的反馈 1，第三轮）：画板里本来就没有这条说明带，它是基线 `ce8d7e6c` 已有的功能（`283e83aa` “为设置增加效果说明和草稿配色预览”引入），第一、二轮实现把它保留了下来——页面标题与分区锚点之下一条说明带（一句结果说明、“查看草稿效果”链接、折叠的“影响位置与检查方法”），与页面说明、导航橙点、页头“未保存修改”、保存栏重复。用户体验后要求去掉，现整条删除；基线里的 `SettingsEffectGuide.vue`、`settings-category-guide.ts`（每页固定五段说明）一并删除，依赖它们的既有测试已改写（见任务记录“测试预期变更”）。看草稿效果的入口就是页头的“前端预览”按钮。`docs/plans/settings-effects.md` 等更早任务的记录仍按当时的状态描述这条说明带，不再代表现状。
11. 结构化分组全部默认展开（反馈 3）：`details.structured-item` 一律展开，不再有“默认展开路径白名单”；收起只是页面上的临时操作，不写入设置。“代码与原文”里的完整配置原文不是结构化分组，**有意保持折叠**（整份原文是一个大文本框，默认展开会增加误改风险）；用户已确认（2026-11-04 答复“保持折叠”）。代价是页面变长：页面与侧栏有 107 个分组，1280 宽时内容区约 39,800px（折叠时约 2,150px）。
12. 分组标题行与目录间距（反馈 2、3）：分组标题行改为“箭头 | 名称与状态 | 恢复默认”一行，说明在名称下方并与名称左对齐，名称 14px/600、比字段标签 14px/500 更醒目；宽屏下分组内容每层缩进 24px，手机每层只退进 8px。左侧目录项之间留 4px 空隙（原 1px），目录右侧留 8px，选中项的底色不贴着滚动条。画板没有画这些细节。

### 质量

- 不透明度滑块的键盘聚焦环在手机宽度下由 28px 高变为 44px 高（滑块自身加高了），只在键盘聚焦时可见，是点击区改动带来的外观差异（第二轮用逐像素比较确认过；第三轮页面外观整体有意改变，没有再比较）。
- 手机 + 底部停靠预览：页头、保存栏、预览面板占满视口，键盘聚焦没有可用区域；关闭预览即可。
- 访客反馈页“放弃本页修改”只有一次性的浏览器核实，没有自动化规格。
- 自动配色预览不带 `data-theme`；浅色/深色/自动只验证了预览样式表加载与选项选中，不代表前台真实切换。
- 对比度由页面内取色计算，未做色盲或高对比度系统模式；未用屏幕阅读器实机验证，只核对了无障碍名称、角色和键盘路径。
- 没有 Safari/Firefox 与真机触屏验证；没有生产环境验证。
- 嵌入模式只复核了一部分（见上表），用的是隔离的全新库，不代表有迁移历史的真实库。
- 第三轮：分组全部展开后页面很长（页面与侧栏 1280 宽 39,779px、390 宽 43,693px），没有“全部收起 / 全部展开”控件；收起状态只在页面上、不保存，刷新、换页或“放弃本页修改”后回到默认展开；靠后的页内锚点平滑滚动约 1.5 秒。
- 第三轮：“代码与原文”里的完整配置原文是对“设置项全部展开”的有意例外，仍默认折叠；用户已确认（2026-11-04 答复“保持折叠”）。
- 第三轮：页面与侧栏的两张整页图被截在 13,000px，不是完整整页；整页没有溢出、分组全部展开等结论来自探针与规格 U1–U4。
