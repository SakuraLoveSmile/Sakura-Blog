## 目标与范围

用户在 Console「系统设置」里能更快找到、看懂并安全地修改设置：

1. **设置内容简单可视化**：行内展示名称、效果说明与最合适的控件（开关、分段选择、可选卡片、颜色、示意），不再是一长串同质表单。
2. **设置项排版合理**：左侧名称/说明、右侧控件的“行”版式，分区标题 + 页内锚点，手机端上下堆叠。
3. **设置项分类归属合理**：13 个横向 Tab 重组为 5 组 12 页的纵向分组导航，每个设置项只有一个归属；手机端为“分组列表 → 详情”。

明确不做：后端、API、schema 与字段路径变更；AI 与知识库（仍在「助手 · 设置」，设置导航底部仅放跳转入口）；公开 Stellar 前台；Console 应用外壳（全局侧栏、顶栏）。设置语义（保存协议、默认值继承、只写用户修改的节点、未知字段保留）不变。

旧链接兼容：`basic→site`、`search→seo`、`plugins|tag_plugins|services|default→extensions`、`rightbar→layout`、`stellar2→advanced（展开完整配置原文）`，其余沿用原 `legacyTabMap`；`ai→/assistant?tab=settings`、`security→/profile` 保持；无 `tab` 或未知值落到站点信息。

**保存模型**：除站点信息、访客反馈外的 10 页共享同一份主题草稿，页面底部统一保存栏显示“N 处未保存修改”及分页计数，按钮“保存全部主题设置”。站点信息、访客反馈各自独立保存（站点/反馈分段），保存栏文案为“仅保存本页；主题草稿另有 N 处未保存”，按钮“保存”。两种页面都有“放弃本页修改”，只还原本页字段，其他页草稿保留。

**行内状态语义**（与画板的有意差异）：画板的故事是全新安装，“已修改”同时等于“未保存”也等于“已覆盖默认”。真实数据里二者不同，因此：橙色圆点只表示“相对上次保存有未保存修改”；“恢复默认”的作用是移除草稿里对该字段的显式覆盖（改回主题默认），所以只在草稿里**存在显式覆盖**（或有尚未同步的输入）时出现，与值是否恰好等于默认无关。结果是：已保存的覆盖有“恢复默认”、没有橙点；点了“恢复默认”后有橙点（相对已保存值有改动）、没有“恢复默认”（覆盖已不存在）。打开页面、浏览、切换页面都不会写入配置或补写默认值。主题外观页另有页面级“恢复主题外观默认”，按同一规则仅在 `theme.appearance` 下存在显式覆盖时出现。

**依赖项**：总开关关闭时（如“启用文章扩展”），其依赖项整行变淡（透明度 .5）但仍可编辑——保持现有“可提前配置”的语义（画板为置灰，此处刻意不禁用）。“已关闭；配置保留，启用后才生效”的说明在同一分区里只在第一个依赖项上可见，其余依赖项保留给读屏（视觉上只靠变淡逐行标示），避免同一句话重复十余次。

**预览**：前端预览按钮保留，焦点页面从旧分类键迁到新页面键；仍为只读静态预览，不执行脚本，不写入配置。预览面板沿用既有的底部停靠（打开时保存栏上移到面板上方），没有改成侧栏——画板只设计了页面本体，没有给预览面板指定新位置。

## 实现取舍（相对画板的其他差异）

- **主题外观的控件**：颜色、字体、形状、背景沿用现有 `StructuredSetting` 通用结构化编辑器（含色板、不透明度、示意与已有的恢复默认），没有逐项重画画板里的定制控件；预设、配色模式等选项使用视觉选择。原因：字段路径、默认值、只写用户修改的节点与大整数保护已由该编辑器保证，重画会引入第二套写入路径。
- **结构化节点的开关**：导航、页面与侧栏、扩展等页的嵌套配置仍由 `StructuredSetting` 渲染；其中布尔节点用纯 CSS 把开关放到右侧、名称与说明在左，与规范行一致。模板结构与子节点关系不变，所以 `:scope >` 这类定位与保存路径都不受影响。
- **手机上的分段选择**：占满整行、选项按文字宽度分配（命中区 ≥44px），名称与说明保持完整宽度；只有开关和数字仍与名称同行。对应画板 `MobilePage` 里“段落首行缩进”的堆叠方式。
- **字段名称**：`theme.appearance.preset` 在行内显示为“预设”，`theme.appearance.typography` 显示为“正文排版”（分区标题已是“外观预设”“字体与排版”，原名重复）。仅改展示文案，路径与保存内容不变。
- **导航与响应式**：桌面纵向导航固定宽度 208px，侧栏高度有限时自己滚动，并把当前页显露在可视范围内；手机（≤767px）是分组列表 → 详情，没有 `?tab=` 时先显示列表。
- **设置页内容区**：不再包一层主卡片，导航与内容直接铺在页面容器上，分区只靠留白与分隔线（原“单卡片层级”的 e2e 断言据此改写，见下）。
- **Console 仅深色**：Console 外壳恒挂 `.dark`，没有浅色/自动模式；“浅色/深色/自动”只是前台主题的配色选项（设置项 `theme.appearance.color_scheme`）。验收中的“可读性”因此只在深色界面下核实。
- **sticky 页头与保存栏之下的滚动**：页头与保存栏都是 sticky，会盖住滚到它们下面的内容，而 `main.content` 是跨路由持久的滚动容器（不重置滚动、没有 KeepAlive）。`SettingsView` 用 `ResizeObserver` 量取页头高度与保存栏占用的底部距离，发布为 `--settings-sticky-offset`、`--settings-bar-offset`（页头换行、预览停靠、手机底部留白变化时都会重新量）；分区标题和所有可聚焦控件用 `scroll-margin` 避开两者；首次挂载、换页、手机列表与详情互相切换都把设置页滚到起点（原先只有页面标题上的 `scrollIntoView({block:"nearest"})`，既不处理进入时残留的滚动位置，也没有给分区锚点留页头的位置）。不改 Console 外壳。
- **手机 + 前端预览**：预览沿用底部停靠（65vh），在手机宽度下与 sticky 页头、保存栏合计占满视口，键盘聚焦没有可用区域；关闭预览即可。这是既有的预览方式，不在本任务范围内改动，已作为限制写明（README 差异 8）。
- **手机点击区（只扩大点击区，视觉不变）**：第一轮验收发现手机上有一批控件点击区小于 44px，本任务没有放大它们，交给用户决定；用户答复“只扩大点击区”，于是第二轮只补点击区、不改外观。做法都在 ≤767px 的媒体查询里：开关（共享 `VSwitch`，51×31）、“恢复默认”（48×18）和折叠摘要（21px 高）用透明的 `::before`/`::after` 往上下的空白处延伸（`settings-form.css` 末尾的“手机点击区”块），上下各补多少按量到的真实空隙定，所以不盖到相邻控件、不抢它们的点击；不透明度滑块（28px 高）在 `SettingColorEditor.vue` 里自身加高到 44px，再用负外边距抵回，行高、轨道与圆点位置不变；“X”平台选项的窄标签（29px 宽）在 `CanonicalSettingsForm.vue` 里左右加内边距并用负外边距抵回。选择器限定在 `.settings-content` 之下，桌面与其他 Console 页面不受影响。不放大视觉的理由：结构化节点的样式是既有的，画板没有重画它们；用户明确要求只扩大点击区。已知差异：不透明度滑块的键盘聚焦环在手机宽度下由 28px 高变为 44px 高。数量与证据见 README Q2b。
- **体验反馈（第三轮，2026-11-04）**：用户在 8098 预览里体验后发来三张截图，说“图一这个去掉 图二这个需要有一点间距 图三这里还能再优化一下 设置项全部展开”，按这三条直接实现（不再回到画板；画板里没有这些细节）：
  - **去掉“效果说明条”（图一）**：页面标题与分区锚点之下的那条说明带——一句结果说明、“查看草稿效果”链接、折叠的“影响位置与检查方法”——整条删除，连同 `SettingsEffectGuide.vue` 与 `settings-category-guide.ts`（每页固定五段说明）。这条说明带不是画板里的设计，而是基线 `ce8d7e6c` 已有的功能（`283e83aa` 为设置增加效果说明和草稿配色预览时引入），第一、二轮实现保留了它；所以这是应用户要求删除一项更早任务的功能，两个文件是基线里被跟踪的文件，依赖它们的既有测试已改写（见下“测试预期变更”），`docs/plans/settings-effects.md` 等更早任务的记录仍按当时的状态描述它。它与页面标题下的一句话说明、导航橙点、页头“未保存修改”徽章、保存栏重复；看草稿效果的入口本来就有页头的“前端预览”按钮（同一个条件、同一个开关）。预览失败时的提示由“再查看草稿效果”改为“再查看前端预览”，免得提到一个已经不存在的入口。
  - **目录留间距（图二）**：左侧目录项之间由 1px 改为 4px，选中与悬停的整块底色不再连成一片；目录是自己滚动的容器，原来没有横向留白，选中项的底色会贴着滚动条，所以右侧留 8px（`flex-basis` 同步加到 216px，目录本身仍是 208px 宽——只加 padding 不加宽度时目录内容区缩到 200px，底部“AI 与知识库 · 在「助手」中设置”会折成两行，已由 U3 守住）。手机分组列表不变。
  - **分组全部展开并整理标题行（图三）**：`details.structured-item` 一律默认展开，去掉原来的“默认展开路径白名单”（颜色、字体等几处）；收起只是用户在页面上的临时操作，不产生未保存修改，之后编辑别处也不会把它重新展开，而“放弃本页修改”“恢复默认”会按已保存值重建该页或该分组的表单，分组随之回到默认展开。“代码与原文”里的完整配置原文**不算结构化分组，有意保持折叠**（整份原文是一个大文本框，默认展开会增加误改风险，页面里也有提示“请展开…”）；这个对“设置项全部展开”的例外问过用户，答复“保持折叠”（2026-11-04），所以是用户确认的取舍，不是实现上的遗漏。标题行改为：箭头 | 名称与状态 | 恢复默认 一行，说明在名称正下方、与名称左对齐；名称 14px/600，比下面各字段 14px/500 的标签更醒目（原来分组名比字段标签还小，展开后层级读不出来）；箭头只表示可以收起，展开时转向下。宽屏下分组里的内容每层缩进 24px，与名称对齐；手机只让嵌套的分组每层退进 8px，宽度留给控件。代价：全部展开后页面明显变长——页面与侧栏（14 种页面类型 × 各自的左侧栏、侧栏组件、页脚等）有 107 个分组，1280 宽时内容区约 39,800px（折叠时约 2,150px），其余页：外观 11 个、导航与页脚 11 个、评论 6 个、扩展与服务 42 个；仍可点分组标题逐个收起，页内锚点照常可用。

### 验收中发现并修复的问题

这些大多是在真实浏览器的截图或探针里发现的，单元测试和 `make test` 抓不到。每条末尾写了回归保护；写“无专门用例”的只做了浏览器核实，没有自动化用例守住。

- 前端预览的初始页面：直接打开 `?tab=post` 这类链接时 `active` 从一开始就是该页，不会触发 `watch(active)`，预览初始页停在首页 → `useSettingsPreview` 的 `previewPage` 初值按当前页设定。无专门用例。
- 手机上分段选择把名称与说明挤成窄列 → 分段选择占满整行、命中区 ≥44px。无专门用例，由 390px 截图核实。
- 图标用法变化后 `ri-subset.json` 与源码不一致 → 重新生成。`make test` 的 assets-test 守住（用到的图标必须在子集里、子集里不能有未使用图标）。
- 分区锚点跳转后标题被 sticky 页头盖住；换页后新页的标题被带过来的滚动位置盖住 → 见“实现取舍”的 sticky 一条；规格 N2（12 页全部锚点）、N6 保护。
- 键盘聚焦的控件被底部保存栏盖住（外观页 110 个停靠点中 19 个，其他页同样存在）→ 聚焦控件的 `scroll-margin`；规格 N7 保护。
- 从滚动过的 Console 页面进入系统设置，设置页不从页首开始 → 首次挂载也滚到起点；规格 N6 保护。
- 站点信息标题为空时的拦截：标题带 `required`，保存按钮是表单内的提交按钮，浏览器原生校验先于页面代码拦截并聚焦标题 → 规格 S2 改为断言校验状态与焦点，不再断言 Toast（Toast 只是不执行原生校验时的兜底）。
- 取证工具自己的两处问题（只影响证据，不影响产品）：进入探针在手机列表模式下量到了隐藏的页面标题（读数 0；实际首个分组标题在页头下方 126px，命中测试未被盖住）→ 探针改为只取可见元素并加命中测试，重新跑；状态截图脚本在手机上按 844 裁切丢了底部导航、整页图残留聚焦输入框造成的滚动偏移 → 修正后全部重拍。
- **手机点击区（第二轮，用户指示“只扩大点击区”）**——实现中发现并修掉的问题，都由 `ia` 的 Q2b 全页命中测试保护：①折叠摘要的扩大区最初套在所有 `summary` 上，抢走了引导预览按钮 `button.guide-preview` 的点击（那个摘要本来就是 44px）→ 选择器收窄为 `details.structured-item > summary`；②摘要里嵌套的“恢复默认”的点击区被算到摘要头上，掩盖了摘要自己的缺口 → 测量助手区分嵌套控件，探测线避开嵌套控件所在的列；③标题行里“恢复默认”叠得很紧（相邻按钮只隔 23–25px），统一补同样高度会互相盖住（最初 126 个、调整后 9 个被邻居挡住）→ 上下各补多少按量到的真实空隙分配，给“带子节点的标题行”单独一档，最终 0 个被挡。
- **第一轮文档里的点击区数量口径有误，已更正**：当时写的“756 个控件小于 44px”多算了 18 个取色器原生输入（它们叠在 52×44 的“取色”标签里，可点击的是标签）、只量高度而漏掉宽 29px 的“X”平台标签，滑块也多算了 1 个，并且统计时没有先展开折叠分组。用同一个命中测试助手在改动前的代码上重新量，盒子不足 44px 的是 738 个。README Q2b 与 `verification.json` 已按新口径改写。
