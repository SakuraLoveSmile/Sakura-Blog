# 后台写作体验优化

## 概要

优先改善整体后台的导航、页面布局和操作一致性，以找到文章、开始写作、保存和发布作为验收主线。沿用现有 Apple 深色 UI，不更换组件库或全局 token。用户已授权实施，本说明用于固定施工边界，随后继续实施。

主工作目录：`../Blog-writing-ui`（`codex/writing-ui`）；编辑器专家目录：`../Blog-writing-editor`（`codex/writing-editor`）。根 `Blog` 的 `.gitignore` 已有改动保持原样。独立工作树实现，不推送、发布、部署或清理用户工作树。

## 交付物

- T1：后台侧栏固定写作入口，首页直接开始写作/进入草稿，手机底栏精简为仪表盘、文章、评论、媒体及更多。
- T2：保留现有列表内容和设置布局，页头操作保持可见；文章筛选与 URL 同步，视图偏好记忆、清除筛选及清晰空态，统计明确本页边界。
- T3：编辑页持续保存状态、离开保护、保存/发布互斥；即时正文同步；手机默认专注正文且可切换编辑器、开关设置。
- T4：必需门禁、真实构建、隔离服务浏览器核验与截图。

## 关键设计决策

唯一视觉参照为 `docs/baselines/writing-ui/reference-posts.jpg`（当前 dev 隔离服务截图，默认桌面视口），补充现状 `before-editor.jpg`、`before-editor-mobile.jpg`。沿用 `DefaultLayout.vue`、`VPageHeader.vue`、`VButton.vue` 及 `resource/apple-design` 的语义颜色、圆角、间距，保留其他页面布局和仪表盘用户组件编排。新增操作用既有按钮，触控入口至少 44px；不新增浅色能力。

T1 写作按钮由后端模块可见性与当前 `content:write` 权限决定；不改权限规则。手机入口仍由模块 manifest 决定，仅减少默认 mobile 项，所有其余入口可经更多菜单访问。桌面子菜单只保留原机制。首页新增小型写作区，位于问候与原组件网格之间，保留布局设计器。

T2 页头默认固定可见，显式请求隐藏行为的旧页仍可保留；文章页切换状态更新 URL 并保留其他 query，浏览器返回与草稿入口同步，分类/标签/搜索清除操作恢复第一页。不承诺跨页排序：现有客户端排序明确标为本页排序。现有分页统计不伪装全站数据。加载/错误沿现有查询机制，不把失败解释为空结果。

T3 保存以完整表单快照判断未保存状态，加载完成或已保存快照为基线；保存期间再编辑仍显示未保存，不清新备份。富文本暴露 `flushPendingChanges` 经包装层向上传递；保存、发布、预览、模式切换、离开前 flush 并等待 Vue 同步。只新增持续状态和离开确认，不引入远端自动保存。已发布文章保存草稿不影响线上；独立 AI 摘要仍维持原契约。保存失败保留未保存状态与全局既有错误反馈。手机面板独立于桌面偏好，默认关闭，有关闭按钮与 Escape，保留底部导航安全区。

## 实现步骤

### Step 1（T1）：让常用入口易找

主 agent 独占 `DefaultLayout.vue`、`DashboardView.vue`、`internal/module/core/core.go` 和对应前端 core manifest。复用权限/模块真值与按钮；固定侧栏写作按钮及首页写作区，更新两侧 manifest 的 mobile 约定。不移除菜单，不改变 API/schema。独立调查由只读 analyst 完成编辑路径；主 agent 已观察真实桌面与 390px 手机页面。

检查：桌面收起/展开侧栏均可写作；手机底栏最多 5 项，更多里页面/专栏仍可达；禁用或无权限模块不产生写作入口。

### Step 2（T2）：稳定页头并整理文章管理操作

主 agent 独占 `packages/components/src/ui/VPageHeader.vue`、`PostList.vue`。复用原页头与空态按钮插槽；修改默认隐藏策略、筛选同步与重置、视图 localStorage，补筛选可访问名称与选中状态，统计文案标明本页，沿用现有卡片/表格。

检查：草稿→文章全部→浏览器返回选中状态与 URL 一致；分类/标签/关键词清除；刷新仍保持视图选择；滚动后常用操作可达；390/768/桌面无外层横向溢出。

### Step 3（T3）：编辑页反馈和手机衔接

Sol worker 在独立编辑器工作树独占 `PostEditor.vue`、Console `RichTextEditor.vue` 包装层、`packages/editor/src/RichTextEditor.vue`、`MarkdownEditor.vue`、共享 `useLocalDraft.ts` 和直接需要的编辑器回归测试。读取原保存/草稿/发布流程，遵守上方快照与 flush 规则。无下级派发：这些状态共享一条保存链，需同一责任人完成。主 agent 不并行写这些文件，收回 diff 后集成至主工作树。

检查：标题、正文和元数据更改均提示未保存；放弃/继续编辑确认；保存失败与保存期间再次编辑；立即输入后保存/预览/模式切换不丢最后内容；手机开关设置不遮住初始正文，切换编辑器可用。补有意义的行为测试，复用 `editor-publish.spec.ts` 验证真实写作发布。

### Step 4（T4）：集成、验证及交付

主 agent 集成专家 diff，运行 `make test`、`make build`、`git diff --check`；相关现有 E2E 在 `scripts/e2e/run-server.sh` 创建的隔离根目录中运行，数据库/内容/配置/附件不访问用户真实数据。服务构建后重启，核对 HTML 引用资源与 dist hash。主 agent 用真实浏览器走首页→草稿→新建→编辑→保存→预览/发布，核验 390px、768px 和默认桌面视口，截图放同一 baseline 目录。

必要验证完成标记“待体验”，用户确认后才“已验收”。本次实现按仓库流程本地提交并通过 `make merge-check` 合入 dev；外部发布另需授权。本次进程和隔离服务作为体验入口保留；不顺手删除工作树或分支。
